# مِسار — نظام إدارة مدرسة

## التشغيل
1. ثبّت Python 3.9+ (لا مكتبات إضافية). 2. انسخ `.env.example` إلى `.env`. 3. شغّل `run_masar.bat` (ويندوز) أو `./run_masar.sh`.
3b. ضع في `.env` السطر `MASAR_ACCESS_CODE=رمز-تختاره-أنت`.
4. افتح http://127.0.0.1:8787 — شاشة فيها «تسجيل الدخول» و«إنشاء حساب مدير». الإنشاء يتطلب رمزك؛ من أدخله صحيحًا ينشئ حساب مدير بالاسم وكلمة المرور التي يختارها، وبعدها يدخل بهما دائمًا. لا حد لعدد الحسابات. بعد 5 محاولات خاطئة (دخول أو رمز) يُقفل المصدر 5 دقائق.
من أجهزة أخرى في الشبكة: `http://IP-الجهاز:8787`.

## المعمارية
واجهة ← API ← SQLite واحدة (`data/masar.db`) = مصدر الحقيقة. لا localStorage للبيانات. الواجهة لا تُظهر نجاحًا إلا بعد تأكيد السيرفر.
Worker داخل السيرفر يعمل والمتصفح مغلق: يفحص الأقساط المتأخرة ويرسل الإشعارات من `notification_outbox`.

## الأدوار
admin (كل شيء + مستخدمون + حذف نهائي + نسخ) | management | teacher (حضور ودرجات) | accountant (مالية) | read_only. الحماية في السيرفر.

## الأقساط
عند إضافة قسط حدّد "التجديد كل كم شهر". عند السداد الكامل: يُلغى إشعار التأخير، يُنشأ القسط التالي، ويصل ولي الأمر رسالة بالمبلغ وآخر موعد.

## واتساب (يحتاج بياناتك)
- الإرسال: `WHATSAPP_ACCESS_TOKEN` + `WHATSAPP_PHONE_NUMBER_ID` + `WHATSAPP_TEMPLATE_NAME` (قالب معتمد جسمه `{{1}}`).
- الاستقبال: في لوحة Meta سجّل Callback URL = `https://نطاقك/api/whatsapp/webhook` (يلزم عنوان HTTPS عام، مثل Cloudflare Tunnel/ngrok/Nginx) و Verify Token = `WHATSAPP_VERIFY_TOKEN`، واشترك في حقل `messages`، وضع `WHATSAPP_APP_SECRET`.
- الرسائل الواردة تظهر في ⚙ لوحة المدير مربوطة بالطالب عبر رقم ولي الأمر.

## النسخ الاحتياطي وحماية البيانات على Render

**تحذير مهم:** النسخ اليومية داخل `backups/` موجودة على نفس نظام الملفات الذي توجد فيه قاعدة البيانات. على خدمة Render المجانية يمكن أن تُفقد قاعدة SQLite والنسخ المحلية عند إعادة النشر أو إعادة التشغيل أو السكون؛ لذلك هذه النسخ المحلية وحدها ليست حماية من فقدان الخدمة.

- في لوحة المدير، استخدم **«تنزيل نسخة خارج الخادم»** بانتظام، واحفظ الملف على جهاز موثوق ثم انسخه إلى مكان مستقل وآمن. لا ترفع ملفات قاعدة البيانات إلى المستودع العام ولا تشاركها؛ فهي تحتوي بيانات الطلاب.
- **للتشغيل المستمر على Render:** يلزم قرص دائم لخدمة مدفوعة أو نقل البيانات إلى قاعدة بيانات مُدارة. ملف `render.yaml` المقترح يربط القرص عند `/var/data` ويضبط `MASAR_DB` و`MASAR_BACKUPS` على ذلك المسار. لا تُزامن الـ Blueprint قبل مراجعة التكلفة والتأكد من إعداد الخدمة الصحيحة.
- قبل تغيير مسار التخزين أو إضافة القرص، نزّل نسخة احتياطية مستقلة. عند بدء التشغيل، يحاول النظام نسخ قاعدة `data/masar.db` القديمة إلى المسار الجديد فقط إذا كان الهدف غير موجود، ويتحقق من سلامة SQLite ويُبقي المصدر كما هو. **هذا لا يضمن العثور على قاعدة الأمس** إذا كان Render قد أزال نظام الملفات المؤقت بالفعل.
- بعد أي نقل، سجّل الدخول وتحقق من عدد الطلاب والمعلمين والسجلات المالية والحضور، ثم أنشئ نسخة احتياطية جديدة ونفّذ اختبار استعادة في بيئة منفصلة قبل الاعتماد التشغيلي.

إنشاء نسخة على الخادم متاح من ⚙، والتنزيل المستقل متاح من الزر الجديد. الاستعادة: من ⚙ أو `python restore_backup.py اسم_الملف.db` والسيرفر متوقف.
